# worktree-env 配置参考

按 worktree-env 0.8.0 的 `profiles.py`、`projector.py`、`config.py`、`paths.py`、`hooks.py`、`registry.py` 和 `cli.py` 核对。项目：https://github.com/archcst/worktree-env 。操作时优先核实已安装版本；需要查询在线资料时使用当前环境提供的网页检索能力，不要求存在源码仓库。

## 目录与命令

配置目录优先级：`WTE_CONFIG_HOME` → `$XDG_CONFIG_HOME/wte` → `~/.config/wte`。下面用 `<config-home>` 表示实际目录，不要把这个占位符直接执行。

| 路径 | 用途 |
| --- | --- |
| `<config-home>/config.yaml` | 端口池 |
| `<config-home>/<project>.yaml` | 活跃项目 Profile |
| `<config-home>/project.example.yaml.template` | `wte init` 生成的非活跃模板 |
| `<config-home>/secrets/<project>/` | skill 迁移本机配置时默认使用的外部源目录 |
| `<config-home>/backups/<project>/` | skill 迁移时的私有回退备份 |
| `<config-home>/hooks/` | 全局 Git Hook 分发器 |
| `<config-home>/state/` | wte 管理的状态，不手工编辑 |

根目录扫描 `.yaml`、`.yml`、`.json`，排除 `config.yaml`；同 stem 时优先 yaml，再 yml，再 json。Profile 名及 main-worktree 匹配应唯一；使用不同文件名但同一主工作树会冲突。

| 命令 | 影响 |
| --- | --- |
| `uv tool install worktree-env` | 用户级安装应用 |
| `uv tool upgrade worktree-env` | 升级已安装应用；需要时经批准刷新 Hooks/Monitor |
| `wte init` | 初始化配置/模板，安装 Hooks，修改全局 core.hooksPath |
| `wte doctor` | 诊断结构、注册表、Secrets 路径、Hooks 和 Monitor |
| `wte list` | 显示仍存活的 worktree 分配 |
| `wte sync` | 投影当前 worktree 并启动 setup-commands；`--rebalance` 丢弃已保存分配并整块重新分配 |
| `wte monitor enable` | 安装/刷新宿主机监控 |
| `wte monitor disable` | 移除监控，保留 Hooks |
| `wte uninstall` | 移除所有 wte Hooks 和 Monitor，保留配置和运行状态 |

没有公开的 Profile 验证子命令或 sync dry-run。不要调用 `_hook`、`_reconcile` 等内部命令代替用户操作；它们有执行副作用。

### 自动投影的范围

0.6.0 的 Monitor 从各 Profile 所属仓库的 `git worktree list` 获取候选，投影尚未注册的 worktree，可能包含主工作树；并不按当前所在 worktree 或服务代码是否存在来过滤。投影可创建缺少的父目录，缺少服务代码不意味着没有文件变更。

`match.main-worktree` 匹配整个仓库的工作树，不支持在 Profile 中按分支筛选。已注册 worktree 也可能经 checkout Hook 或显式 sync 重新投影。启用/恢复 Monitor 的实际处理范围可能跨多个已配置项目；按主流程核实各受影响 worktree，不把只在当前目录执行 sync 当作限制自动范围的措施。

`wte monitor disable` 只移除监控；需核实结果，不能把它当成禁用 Hooks、阻止手动 sync 或终止所有已启动初始化进程的命令。恢复前须单独确认授权和最新影响范围。

## 端口池

```yaml
port-range:
  start: 20000
  end: 29999
```

范围包含首尾，界限在 1–65535，start 不大于 end；通常保留默认值。所有使用同一配置目录的 Profile 共用注册表。

分配语义（0.8.0+）：

- worktree 首次注册时，按声明顺序分配一个连续块。
- 此后修改 `port-claims` 是增量的：新增 claim 只为新 id 分配端口（优先紧邻原块扩展），被删除 claim 的端口释放；已有 id 的端口不动，因此块可能不再连续。
- 单个已保存端口被其他 worktree 占用或越出端口池时，只重分配该端口，不影响其他 id。
- Profile 身份（name 与文件名）都不匹配、注册项丢失，或显式 `wte sync --rebalance` 时，才丢弃旧块并重新分配一个连续块。

分配不是持有监听 socket；它不能防止其他程序后来抢占端口，也不负责启动服务。重排会让旧端口上的服务失效，`--rebalance` 后应按新分配重启相关服务。

## Profile 字段

| 字段 | 规则和注意事项 |
| --- | --- |
| `name` | 非空、唯一名称；更新时尽量保持 |
| `match.main-worktree` | 主工作树绝对路径，可用 `~` 或 `$HOME`；不是分支、remote URL 或路径 glob |
| `port-claims` | 至少一项；每项有 `id`，同 Profile 内唯一，匹配 `[A-Za-z_][A-Za-z0-9_]*`，且不得占用保留名 `worktree`/`worktree_slug`；首次分配按声明顺序组成连续块，后续增删是增量的 |
| `link-files` | 可选列表；每项 `source` + `target`；源使用仓库外绝对/家目录路径，目标是工作树内相对路径；0.7.0+ 同时支持文件和目录源 |
| `write-files` | 可选列表；每项 `target` + `body`，可指定 `header`；整文件覆盖 |
| `setup-commands` | 可选列表；每项 `command` 为非空字符串数组，`args` 为字符串数组，`cwd` 为必填路径，`skip-if` 可选 |

使用规范键，不在新配置中引入历史别名。字段校验不能替代检查应用加载行为和目标文件安全性。

### 模板不是 shell

`write-files.body` 使用 Python `string.Template.substitute`，注入两类变量：port id 对应的数字，以及内置的 `${worktree}`（worktree 目录名）和 `${worktree_slug}`（小写、`[a-z0-9-]`，用于 compose 项目名等场景；0.8.0+）。推荐 `${frontend_port}` 形式；未知变量和非法 `$` 语法会失败。想输出字面量 `$` 时用 `$$`，例如 `API_TOKEN=$${API_TOKEN}` 会输出 `API_TOKEN=${API_TOKEN}`，是否再次展开取决于应用，不是 wte 的功能。

`$HOME` 在路径字段中的展开与 body 中的模板变量是两回事。不要在 body 中放 `${HOME}`、`${name}` 并期待 wte 注入；不要用 shell 插值提前展开 YAML 草案，写文件用能保留字面量的工具/带引号 heredoc。

### 生成文件格式

默认在 body 前插入：

```text
# Generated by wte; changes will be overwritten.
```

适合允许 `#` 注释的 dotenv/YAML 等格式。对 JSON 等不允许注释的格式，0.6.0 可显式设置 `header: "\n"`，用合法空白代替默认注释，并校验最终文件语法。`header: ""` 在该版本会回退到默认注释，不能用来禁用 header。其他版本先检查实现。

### Secrets 与写入顺序

用户仓库内已有本机配置时，按 [本机配置迁移流程](migration.md) 分类、审批、复制校验和链接回原路径。`wte` 自身不会搬出或备份原文件；必须在投影前完成保护。

先应用 `link-files`，再应用 `write-files`。源缺失会跳过链接并给出提示，不代表环境完整。软链接目标已有普通文件/链接时会先删除；write 目标是链接时也会先删除链接，然后生成普通文件，不会合并内容。

0.7.0+ 的 `link-files.source` 可以是目录，同样创建软链接；已正确指向源的链接保持不变，目标已有真实目录时报错，不会删除或合并。目录中的新增文件自动可见，通过任一 worktree 修改内容都会影响共享源。`doctor` 和投影前检查会拒绝相同或互相嵌套的目标；投影也会拒绝源目标重叠造成的自引用。目录迁移需单独制定递归备份和校验方案。

不要让两个动作指向同一个文件，也不要把整个共享 `.env` 覆写成只有端口的文件。如果项目仅加载一个环境文件，需要确认可用的本地分层机制；无法表达时明确限制，不通过将 Secrets 值嵌入 body 来凑配置。

### 初始化命令

```yaml
setup-commands:
  - command: [npm]
    args: [ci]
    cwd: apps/web
    skip-if: node_modules
```

仅适用于 `apps/web` 自身有对应 npm 锁文件的项目；monorepo 可能需要在根目录安装。根据项目选用 pnpm/yarn/uv 等，不机械复制。

0.6.0 直接以参数数组启动进程，没有隐式 shell 展开；`&&`、管道、重定向和 `$VAR` 不会自动执行或替换。`cwd` 相对 worktree 根目录解析，`skip-if` 相对 cwd；优先使用工作树内路径。确实需要显式 shell 时审阅完整命令并获批。

命令在后台启动，没有依赖顺序保证或成功等待。不要把有前后依赖的任务放成多个独立项并假设串行执行。日志写入系统临时目录中的 `wte-init-*.log`，可能含安装脚本的敏感输出。

## 最小双服务示例

**适用前提**：已确认 web 启动配置读取 `.env.development.local` 中的 `DEV_SERVER_PORT` 作为监听端口；前端读取 `VITE_API_URL`；api 确实加载同名本地文件中的 `PORT` 和 `CORS_ORIGIN`。这些变量和文件名是示意，不是通用框架约定。两边还会加载各自 `.env`，本地动态值拥有所需优先级。

```yaml
name: example-app

match:
  main-worktree: $HOME/code/example-app

port-claims:
  - id: web_port
  - id: api_port

link-files:
  - source: $HOME/.config/example-app/web.env
    target: apps/web/.env
  - source: $HOME/.config/example-app/api.env
    target: apps/api/.env

write-files:
  - target: apps/web/.env.development.local
    body: |
      DEV_SERVER_PORT=${web_port}
      VITE_API_URL=http://127.0.0.1:${api_port}
  - target: apps/api/.env.development.local
    body: |
      PORT=${api_port}
      CORS_ORIGIN=http://127.0.0.1:${web_port}
```

示例不含初始化命令，端口与 Secrets 的文件分开；源文件必须先准备，全部投影目标应未被 Git 跟踪且已被忽略。单服务按需求缩减，不能为了通过校验虚构没有用途的端口。

## 常见排查

| 现象 | 检查方向 |
| --- | --- |
| 当前 worktree 无匹配 Profile | 有效配置目录、main-worktree 的真实路径、重复 Profile、文件是否被加载 |
| Hooks 显示安装但未同步 | 仓库级 hooksPath 覆盖、Git/IDE 是否执行 Hook、GUI 环境与配置目录、可执行路径是否因升级失效 |
| Git 成功但环境未准备 | post-checkout 的 wte 错误会 fail-open，Git 成功不能证明投影成功；查脱敏日志和 doctor |
| 端口文件已生成，服务仍用默认端口 | 应用是否加载该文件/变量，shell/CLI 优先级，HMR/代理是否另有配置 |
| Secrets 文件缺失 | source 是否为真实文件，宿主机/沙箱权限和路径是否一致；不打印值 |
| 修改 Profile 后老 worktree 未更新 | Monitor 处理未注册 worktree（可能含主工作树）；已注册者按批准范围显式 sync |
| Monitor 未启用 | 仅在需要沙箱补偿时启用；macOS 为 LaunchAgents，Linux 为 systemd user path units |
| 多实例仍冲突 | Docker 名称/卷、数据库数据、额外调试端口、未纳入映射的服务；这些不会自动隔离 |
| 端口池耗尽或注册表损坏 | 检查存活 worktree 与池容量；不手改/删除 state 来重置，先备份并制定修复方案 |
| 想主动重排或收紧已不连续的端口块 | 逐个 worktree 执行 `wte sync --rebalance`，并按新分配重启旧端口上的服务 |
